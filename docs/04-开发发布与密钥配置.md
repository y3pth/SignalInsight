## 2. API Key 安全配置教程

### 原则

- 密钥不得粘贴到聊天、源码、Git、命令行参数或普通日志。
- Qoder Sites 的 Secret 值只写不可读回。
- 当前 MCP 没有写入 Secret 值的工具。
- 当前机器没有安装 Qoder CLI，`qoder` 命令不在 PATH。

### 第一步：安装 Qoder CLI

Windows PowerShell：

```powershell
irm https://qoder.com/install.ps1 | iex
```

验证：

```powershell
qoder --version
```

如果命令不存在，关闭并重新打开终端；Windows 推荐使用 Windows Terminal。npm 方式仅作为兼容方案：

```powershell
npm install -g @qoder-ai/qodercli
```

如果全局 npm 目录无写权限，可安装到当前用户目录：

```powershell
npm install -g @qoder-ai/qodercli --prefix "$HOME/.qoder-cli" --cache "$HOME/.npm-cache"
```

随后使用 `$HOME/.qoder-cli/qoder.cmd` 或将该目录加入用户 PATH。

当前机器已经通过该方式安装 Qoder CLI 1.1.89，目录为 `$HOME/.qoder-cli`，但尚未加入 PATH。PowerShell 中使用完整路径：

```powershell
& "$HOME\.qoder-cli\qoder.cmd" --version
& "$HOME\.qoder-cli\qoder.cmd"
```

### 第二步：登录 Qoder CLI

在项目目录运行：

```powershell
qoder
```

进入交互式提示符后输入：

```text
/login
```

选择 `Login with Qoder Platform (Browser)`，在浏览器中完成与当前 Sites 所属账号一致的登录。

### 第三步：打开 `/sites` 面板

在 Qoder CLI 交互式提示符中输入：

```text
/sites
```

在面板中：

1. 选择站点 `SignalInsight`；
2. 打开站点详情；
3. 进入“环境变量 / Secrets”；
4. 点击添加；
5. 名称填写：`DASHSCOPE_API_KEY`；
6. 值填写百炼 API Key；
7. 保存，等待同步完成。

密钥保存后不会再显示明文，只能替换或删除。

### 第四步：重新发布 AI 版本

回到 Qoder Desktop 对话，告知“已配置 DASHSCOPE_API_KEY”。Agent 将：

1. 读取 `get_site(include: ["secrets"])` 验证同步状态；
2. 使用已准备的 action `44149eab-d4f3-4dca-8da6-583ca2447c18` 重新检查；
3. 发布 Qwen 版本；
4. 调用线上 `/health`，确认 `configured:true`；
5. 生成一次真实 Qwen 解释并检查证据约束。

默认模型为 `qwen-plus`，默认兼容端点：

```text
https://dashscope.aliyuncs.com/compatible-mode/v1
```

如果账号不支持默认模型，需要准备新的 Sites 版本并声明 `QWEN_MODEL` 或 `DASHSCOPE_BASE_URL`。

## 6. 故障处理

- Function health `configured:false`：Secret 未同步。
- `service_not_configured`：密钥缺失，前端回退规则解释。
- 上游失败：检查模型/端点、账号额度和网络；不要记录密钥。
- 站点发布状态以 Sites `published:true` 为准，不以本地构建成功代替。
