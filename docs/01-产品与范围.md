# 产品与范围

## 1. 问题

通信与信号处理实验通常需要人工判断信号模型、选择参数估计方法、比较拟合结果并解释物理意义。常见问题包括：

- 面对未知观测时难以提出候选模型；
- 只依据拟合曲线或 R² 判断模型，忽视残差和不确定性；
- 采样不足、噪声或模型失配时仍给出看似精确的结论；
- 数学参数与通信物理意义之间缺少解释桥梁。

## 2. 产品定位

SignalInsight 面向通信、电子信息及相关专业学生与实验人员，提供从数据到结论的可验证分析链路：

```text
观测数据 → 特征 → 候选模型 → 参数估计 → 模型竞争 → 可信度证据 → AI 解释
```

核心差异化：

1. 从单模型拟合转向多模型竞争；
2. 从结果展示转向残差和可信度证据；
3. LLM 只解释确定性结果，不产生或修改数值结论。

## 3. 当前提交版范围

### 已实现

- 单通道实数、近似均匀采样的 CSV；
- 内置单频、双频和库外噪声示例；
- 单频与多频正弦模型，最多 3 个频点；
- Hann 窗 FFT、谱峰候选、变量投影和频率精化；
- RMSE、R²、AIC、BIC、残差 ACF 和残余谱；
- `reliable / caution / unreliable / insufficient_evidence` 证据等级；
- unknown 拒判；
- 结构化规则解释、Qwen 解释入口、报告 JSON 导出；
- Qoder Sites 公开部署和 Edge Function。

### 暂不包含于线上提交版

- AM、FM 自动辨识；
- MAT 文件和变量树；
- 多通道批量分析；
- 复数和 I/Q 建模；
- 非均匀采样；
- Python FastAPI/SQLite 云端部署；
- 用户系统、共享历史和持久化数据库。

这些能力仍保留在完整后端规划与仓库代码中，但不得描述为线上已可用。

## 4. 用户流程

1. 打开站点，默认加载单频示例并立即展示结果；
2. 切换双频示例观察多模型竞争；
3. 切换 noise 示例验证 unknown；
4. 上传 CSV，确认时间列和信号列；
5. 查看推荐模型、参数、指标、残差和证据；
6. 点击 AI 解释（配置 Qwen 后）或阅读确定性解释；
7. 导出 JSON 报告。

## 5. 成功标准

- 无噪声单频频率误差小于 0.05 Hz；
- 双频两个分量可恢复且 BIC 选择多频模型；
- 纯噪声进入 insufficient evidence；
- 所有可信结论可展开到证据；
- 核心分析不依赖网络和 LLM；
- 公开站点匿名可访问，控制台无应用错误。
